# 잔여배차 처리 자동화 — Dispatch v2.0 + 운송사 수기공고 직접 등록

> 포트폴리오 / 이력서용 원본 내용. 수치는 Jennifer 확인 기준 (2026-09-30 정리).

## 한 줄 요약
잔여배차 1곳을 채우는 데 드는 커뮤니케이션 시간을 **건당 20분 → 5분 이내(75% 단축)**로 줄였다.
토요일 기준 **약 700분(11시간 40분)**의 운영 시간을 절약했다.

## 문제
- 잔여배차(확정 후 남은 배차 자리) 1곳을 채우려면 운영팀과 운송사가 채널톡으로 직접 주고받아야 했다.
  (필요 인원 공유 → 구인 → 라이더 연락처·프로모션 공유 → 남은 인원 갱신)
- 이 전체 과정의 커뮤니케이션에만 **1곳당 약 20분**이 걸렸다.
- 토요일 기준 약 100건이 이 과정을 거쳤다.

## 해결 (2단계)

### 1단계 — Dispatch v2.0 (잔여배차 개편), 2026-07-01 배포
- 역할: 기획
- 내용: 잔여배차 매칭을 시스템이 자동으로 처리하도록 개편
- 결과: 토요일 평균 **40건 자동 처리**, 건당 **10분 절약**
  → 토요일 **40 × 10분 = 400분** 절감
  → 건당 처리 시간 20분 → 10분

### 2단계 — 운송사 수기공고 직접 등록 + 수기 공고 개선
- 역할: 기획
- 내용: 운송사가 잔여배차 공고를 직접 올릴 수 있게 함 (운영팀 중계 제거)
- 결과: 나머지 **60건**도 건당 평균 **5분 이상 추가 절약**
  → 토요일 **60 × 5분 = 300분** 이상 절감
  → 건당 처리 시간 10분 → **5분 이내**
- 배포 시점: (확인 필요)

## 성과 정리
| 구분 | 대상 (토요일) | 건당 절약 | 토요일 절감 |
|---|---|---|---|
| Dispatch v2.0 자동 처리 | 40건 | 10분 | 400분 |
| 운송사 수기공고 직접 등록 | 60건 | 5분 이상 | 300분 이상 |
| **합계** | **100건** | — | **약 700분 (11시간 40분)** |

최종: 건당 **20분 → 5분 이내 (75% 단축)**

면접이나 포트폴리오에서 근거로 쓸 수 있는 실측값이다. 위 절감 시간과는 별개 지표다.

- 대상: 토요일 배차, 14시대(B 윈도우)만. 배포 전은 `dispatch_dispatch`, 배포 후는 `dispatch_v2`.
- 배포 후 **50% 배차 확정 도달 시각이 평균 10분 빨라짐** (14:28 → 14:18).

- 배포 후엔 대부분의 배차가 14시 15분 전후에 한 번에 일괄 확정된다. 배포 전엔 라이더가 한 명씩 수락해서 30분 정도 흩어져 있었다.

## 면접 대비 메모
- 20분 / 10분 / 5분 / 토요일 40건·60건은 **내부 확인 수치**다. 출처(측정 방법)를 설명할 수 있게 준비해 둘 것.
- 채널톡 "상담 요청 후 종료까지 시간"(태그 `버니/운송사요청/추가배차구인요청`)은 전후 평균이 비슷했다 (2시간 14분 → 2시간 13분).
  이 지표는 상담방 오픈~종료 시간이라 실제 커뮤니케이션 소요시간과 다르다. 근거로 쓰지 말고, 질문 받으면 "지표 정의가 다르다"고 설명.
- "40 × 10분" 은 자동 처리된 40건만 계산한 값, "60 × 5분" 은 나머지 60건만 계산한 값이다. 둘을 더해 700분.
